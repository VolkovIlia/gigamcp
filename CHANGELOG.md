# История изменений

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии — [SemVer](https://semver.org/lang/ru/).

## [0.2.9] — 2026-10-29

### Исправлено
- **Опасный пример вызова.** В служебном контексте, напоминании и подсказке модели показывается пример вызова, и ГигаЧат копирует его почти буквально. Для DeckCraft на «о чём открытая презентация?» примером был `open_presentation`, а на «почему только Ц2? смотри всю презентацию» — `new_presentation`, который заменяет открытую презентацию. Теперь в примерах только функции, которые ничего не меняют (у функций с пометкой `readOnlyHint: false` примера не бывает).
- **ГигаЧат крутился во встроенных навыках внутри одного ответа** («Думаю над ответом»: поиск навыков → дата → «Ошибка при вызове инструмента» десятки раз) и не писал блок `mcp`. Теперь GigaMCP видит это по шагам ответа, после второй «Ошибки при вызове инструмента» сам нажимает «Остановить» и напоминает про функции: в авто-режиме сразу, иначе кнопкой. Ответы, где были только поиски без ошибок («Исследование», «Рассуждение»), не останавливаются. Каждое зацикливание в чате получает своё напоминание. Заодно исправлено: пока ГигаЧат печатал ответ, проверка страницы откладывалась до конца генерации.
- В подсказке к каждому сообщению теперь готовый пример вызова, как в первом сообщении: без примера ГигаЧат чаще уходил во встроенные навыки.
- ГигаЧат читал из документа одну часть и отвечал по ней (один слайд из одиннадцати). В правилах теперь сказано: если вопрос про весь документ, сначала прочитать все части — несколько вызовов подряд — и не подменять данные поиском в интернете.
- Лимит результатов в одном сообщении — 60 000 символов вместо 15 000 (поле ввода ГигаЧата принимает до 100 000): одиннадцать слайдов DeckCraft целиком помещаются в один ответ.

## [0.2.8] — 2026-10-29

### Исправлено
- В продолжении диалога ГигаЧат забывал о функциях GigaMCP и по кругу уходил во встроенные навыки и поиск в интернете: полный контекст отправлялся только с первым сообщением. Теперь каждое следующее сообщение несёт короткую подсказку: функции подключены, ответ — блок `mcp`, и какие функции подходят. Если по словам ничего не подошло, подсказка называет функции, уже вызванные в этом чате. Функции, которые меняют данные (`readOnlyHint: false`, например `new_presentation`), подсказка не предлагает никогда. В чате подсказка свёрнута в плашку, в которой виден текст самого сообщения.
- Большие результаты обрезались молча, и модель делала выводы по части данных (например, по одному слайду из одиннадцати). JSON в результатах теперь сжимается без потерь, а обрезанный результат помечен: сколько показано из скольки и что остальное нужно запрашивать частями.
- Слова «слайд», «презентация», «посмотри», «сохрани», «открой» и другие сопоставляются с английскими именами функций.
- Напоминание про функции само называло «[MCP-КОНТЕКСТ]» и поэтому в чате выглядело как служебный контекст.
- Если программа завершалась сразу после запуска, помощник мог сообщить о завершении раньше, чем о запуске, или не сообщить о запуске вовсе. Теперь сообщение о запуске всегда приходит первым.

## [0.2.7] — 2026-10-29

### Добавлено
- ГигаЧат знает папки компьютера, когда подключены локальные программы: помощник сообщает домашнюю папку и «Документы» (на Linux — из `user-dirs.dirs`, например `~/Документы`), а в служебном контексте появляется раздел «Файлы на компьютере пользователя»: путь всегда полный, по умолчанию — «Документы», после сохранения модель называет полный путь и не выдумывает, где лежит файл. Работает для любых локальных программ.
- Установка помощника без интернета: кнопка «Скачать установщик» в панели «Локальная программа (stdio)» собирает установщик из файлов самого расширения и сохраняет в загрузки, а панель показывает команду с путём к нему (`python3 "…/gigamcp-install-host.txt"`; `.txt` — чтобы браузер не задерживал загрузку как опасную). `curl` и доступ к GitHub больше не нужны — на рабочих машинах их часто нет. Для этого расширению нужно разрешение `downloads`.

### Исправлено
- Программа без указанной рабочей папки запускалась в папке, откуда браузер стартовал помощник (у Flatpak — скрытая `~/.var/app/<браузер>/data/gigamcp`), и файлы с именем без пути терялись там. Теперь рабочая папка по умолчанию — домашняя.
- Когда программа завершалась, помощник иногда сообщал об этом раньше, чем дочитывал её вывод: текст ошибки («Программа завершилась (код 1): …») и последние ответы терялись. Теперь вывод дочитывается до сообщения о завершении.

Изменения с папками — в помощнике (теперь v0.2.7). Если установлен старый, панель «Локальная программа (stdio)» пишет «Помощник устарел» и предлагает скачать установщик. Со старым помощником всё работает как раньше, только без папок в контексте.

## [0.2.6] — 2026-10-29

### Исправлено
- ГигаЧат бросал цепочку вызовов на полпути: получив результат, уходил во встроенные навыки («Ошибка при вызове инструмента», «Создал файл») вместо следующего вызова, а GigaMCP после результата не напоминал о функциях вовсе. Теперь напоминание срабатывает и посреди цепочки и повторяет исходный запрос пользователя; итоговый ответ после результата напоминанием не считается.
- Ответ, где была только фраза «Ошибка при вызове инструмента», не распознавался как уход во встроенные навыки; то же с «Подходящие навыки не найдены» и частью отказов («не получила доступа»): в шаблонах `\w` не совпадает с кириллицей.
- Сообщение с результатом прямо говорит, что следующий шаг — снова блок `mcp`, а не встроенные навыки, и повторяет исходный запрос пользователя.

## [0.2.5] — 2026-10-29

### Исправлено
- Браузеры из Flatpak (Chromium и Chrome в Fedora и др.) писали «помощник не установлен», хотя установщик отработал: они ищут помощник в своей песочнице `~/.var/app/<браузер>` и не видят программ компьютера. Теперь установщик регистрирует помощник и там, запускает его вне песочницы через `flatpak-spawn --host` и выдаёт браузеру нужное разрешение. После установки такой браузер нужно перезапустить.

### Добавлено
- Если помощника нет, панель «Локальная программа (stdio)» показывает одну команду установки с кнопкой «Скопировать». Папка расширения больше не нужна: установщик со встроенным помощником прикладывается к каждому релизу (`install-host.py`). У копии расширения из магазина свой ID — панель добавляет его в команду (`--extension-id`), а установщик сохраняет ID, уже записанные в манифест, так что распакованная копия и копия из магазина работают вместе.

## [0.2.4] — 2026-10-29

### Исправлено
- Для запросов вида «какие у меня задачи на Taska» примером вызова становилась `taska_guide`: слово «taska» в имени функции совпадало с «task». Теперь имена сравниваются по словам, а название самой системы в запросе не влияет на выбор функции — первой идёт `tasks_list`.
- Каталог больших серверов стал втрое короче (до ~14 000 символов): с параметрами — только подходящие к запросу функции, остальные — одной строкой имён. Последней строкой перед запросом стоит прямое указание ответить блоком `mcp`.
- Напоминание отправляется не только на «нет доступа», но и когда ГигаЧат ушёл во встроенные навыки («Ошибка при вызове инструмента», «запрос относится к системе управления задачами») или просто не вызвал функцию на запрос про подключённую систему. В напоминании повторяется исходный запрос и пример нужного вызова.

## [0.2.3] — 2026-10-29

### Исправлено
- ГигаЧат принимал подключённые функции за свои встроенные навыки: запускал «поиск подходящих навыков» и формы с вопросами, уходил в бесконечное «Думаю над ответом» и падал с ошибкой. Служебный контекст и напоминание теперь говорят о «внешних функциях GigaMCP», прямо запрещают искать их среди навыков и показывают, что достаточно написать блок `mcp`.

## [0.2.2] — 2026-10-29

### Исправлено
- ГигаЧат отвечал «у меня нет доступа к твоим данным», хотя инструменты подключены. Служебный контекст переписан: прямо сказано, что доступ есть и отказываться нельзя, а для образца дан пример настоящего вызова из подключённого каталога.
- Для больших серверов (например, у Taska сотни инструментов) первыми с полными параметрами идут инструменты, которые подходят к запросу; русские слова сопоставляются с английскими именами инструментов (задачи → tasks).
- Если модель всё же ответила «нет доступа», под ответом появляется кнопка «Напомнить про инструменты». В авто-режиме напоминание отправляется само, один раз.

## [0.2.1] — 2026-10-29

### Исправлено
- «Вход выполнен, но доступ запрещён (403)» на серверах с защитой от DNS rebinding (FastMCP и др., в том числе Taska): они отклоняли заголовок `Origin: chrome-extension://…`. Теперь фон расширения обращается к MCP-серверам без `Origin`, как настольные клиенты.
- В тексте ошибки 403 показывается причина из ответа сервера.

## [0.2.0] — 2026-10-29

### Добавлено
- **Локальные программы (stdio) прямо из расширения.** Помощник `extension/host/gigamcp_host.py` на Python 3.6+ без зависимостей. Браузер сам запускает его через Native Messaging, а ставится он одной командой от обычного пользователя: `python3 host/install-host.py`. Поддерживаются Chrome, Chromium, Яндекс Браузер, Edge, Brave, Vivaldi, Opera на Linux, macOS и Windows.
- Форма «Локальная программа (stdio)»: команда, аргументы, переменные окружения, рабочая папка. Подходит, например, для `wordcraft-cli mcp`.
- Импорт конфига в формате Claude Desktop, Cursor и VS Code (`mcpServers`): программы и адреса добавляются разом.
- Ответы больше 1 МБ от локальных программ передаются по частям.

### Исправлено
- Вход через OAuth на серверах, чья страница согласия запрещает переход на внешний адрес (`form-action 'self'` в CSP, как у Taska). Первый клик «Разрешить» выдавал код, но браузер блокировал возврат в расширение, а второй клик сервер отклонял. Теперь код читается из ответа сервера.

### Удалено
- Мост на Node (`bridge/`): его заменил помощник на Python, которому не нужен отдельный запуск и Node.

## [0.1.0] — 2026-10-29

Первый публичный выпуск.

### Добавлено
- Кнопка **MCP** у поля ввода giga.chat и панель управления серверами.
- MCP-клиент: Streamable HTTP с откатом на HTTP+SSE, переподключение при потере сессии.
- Авторизация: Bearer-токен и OAuth 2.1 (RFC 9728, RFC 8414, RFC 7591, PKCE, RFC 8707). Вход идёт в обычном окне браузера, поэтому работают страницы с кодом подтверждения и повторный ввод после ошибки.
- Мост `bridge/gigamcp-bridge.mjs` для локальных stdio-серверов: только 127.0.0.1, токен, защита от DNS rebinding.
- Текстовый протокол вызовов: служебный контекст, карточки вызовов, авто-режим с ограничением шагов, сжатый каталог и `mcp/describe` для больших серверов.
- Логотип «Машиночитаемая реплика» и иконки расширения.
- Тесты: MCP-клиент, OAuth, мост и протокол на Node; e2e с настоящим расширением в Chromium.
